# Decisions

These are choices the owner has made for chibi-v2. Each entry states the decision, its date, and the reason or evidence behind it. Open questions are listed in [research/README.md](research/README.md), and claims still to be measured are in [hypotheses.md](hypotheses.md).

| 2026-11-11 | Integer types (rank 2). `int` is 64-bit on every target and is another name for `i64`. | 2026-11-10 | Inference goes as far as it reliably can, and where it stops, the compiler and the LSP explain why. For errors, every function with a body has its error set inferred, private or `pub`. Function types and `export` functions write their sets, because a function type has no body and a C header is a fixed contract. Writing a set stays allowed anywhere, for example in platform code whose errors differ by target. Proposed with it, not yet decided: bodies are checked without error sets, then one pass over the call graph computes every set, with functions that call each other sharing one set, and the checks that need sets (exhaustive switches over errors, written sets) run after it; messages name where an error comes from; the compiler keeps each `pub` function's inferred set in the package's build output, as OCaml keeps a `.cmi` when there's no `.mli`, so rebuilds and hot reload skip later checks when a set is unchanged, and a set that grew can be reported; `error!T` means any error. A function that can fail and lets the compiler infer its set writes `-> !T`, as in `fn load() -> !Level`, and `-> !void` when it returns nothing (owner, 2026-11-11; first written `-> !`, until `void` became required after `->`, see the `try` row; built in the parser on 2026-11-11). In a private function, leaving out `->` makes the compiler infer the whole return type, both the value type and the errors (owner, 2026-11-11). `pub` functions write `->`, for now, and the owner still wants inference made as good as it can be (owner, 2026-11-11, in the parser thread). A `pub` constant or variable may leave out its type only when finding the type needs no function body: a literal, a typed literal such as `Point.{ … }`, a conversion `T(x)`, a call to a function that writes `->`, or a name whose type follows the same rule. Proposed, not yet decided: a package turns them off in its build description, as Kotlin sets explicit API mode per module; code written with the rules on keeps its meaning with them off, because turning them off only allows more; packages that import a package with the rules off may wait for its bodies again (H14). A `pub` function without `->` returns nothing, as in Odin, Jai, Go and Rust (owner, 2026-11-11), so a `pub` function that returns a value or can fail and has no `->` is an error, and `-> !T` still lets a `pub` function's error set be inferred. Lifting the rule later breaks no code. Proposed with it, not yet decided: the message suggests the type, such as `-> int` or `-> !void`. Proposed with it, not yet decided: in a group of functions that call each other, the return type comes from the `return`s that don't depend on the group, as C++14 takes it from the first such `return`, and a group with no such `return` must write its type. Sets combine with `\|` (see the row after Ranges). The rest of the error design (rank 4) is settled in the rows after Ranges. | Owner's preference. That holds for error sets only. When `->` is left out, a caller's checking needs the callee's value type, so it needs that callee's body checked first. Because declarations are claimed one at a time ([research/README.md](research/README.md), point 1), the caller checks that body itself or waits for the thread checking it; no package waits for a whole other package. The speed cost is those waits and the longest chain of inferred functions, estimated at under 3% of checking ([hypotheses.md](hypotheses.md) H14); a cycle between two waiting threads must be detected. What remains is readability and stability: a body edit can change a `pub` signature, and a wrong return type shows up at the callers. TypeScript 5.5's `--isolatedDeclarations` requires written return types on exports, except "trivial" ones such as `return 20`, for "fully parallel builds" ([announcement](https://devblogs.microsoft.com/typescript/announcing-typescript-5-5/)); Kotlin's explicit API mode requires them so that "API users are aware of the types" ([1.4](https://kotlinlang.org/docs/whatsnew14.html#explicit-api-mode-for-library-authors)); TypeScript 7 instead runs a fixed number of checkers that "may end up duplicating some common work" ([7.0](https://devblogs.microsoft.com/typescript/announcing-typescript-7-0/)). With `->` on every `pub` function, chains of inferred functions stay inside one package, and no package waits for another package's bodies; a `pub` constant typed by a call to a function without `->` would bring that wait back, which the rule for constants prevents. An earlier version of this row overstated the speed cost of inference. The pass is estimated at about 20 cycles per line, not measured ([hypotheses.md](hypotheses.md) H13). Zig works out sets while it analyzes bodies, and its reference lists the costs: such a function "becomes generic", its set can differ between targets, and recursion isn't supported |

| 2026-11-10 | Built in the parser on 2026-11-11: `try`, `catch` with a fallback value, a block or `name =>`, `defer catch`, and the types `E!T` and `!T` (a bare `-> !` was built first, then removed the same day when the `void` rule below was built); `try` and `catch` are keywords. ## Syntax

These were settled with the owner in the parser thread ("AGENTS.md compliance and readability improvements"). Each was checked against Zig, Odin, Jai, C3, Carbon and ZenC. This is a summary as of 2026-11-09; the parser's tests are the exact reference.

| Area | Form |
|---|---|
| Statements | A statement ends at a line break, `;` or `}`; `;` is never required. Otherwise line breaks are ignored, as in TypeScript, so `a` ⏎ `- b` and leading-dot chains continue. Exceptions: `(` or `[` at the start of a line starts something new (outside brackets), and `return` takes its value only from its own line. Line breaks are always ignored inside `( )`, `[ ]`, `.{ }` and `.[ ]`. |
| Expressions | Go's five precedence levels. `and` and `or` replace `&&` and `\|\|`. Comparisons don't chain. Assignment is a statement, not an expression. Wrapping `+%` and `-%` sit with `+` and `-`, `*%` with `*`, and `-%x` with prefix `-`, as in Zig. `??` has its own level between `+` and the comparisons. Postfix `x!!` sits with `.`, `[ ]` and calls. Conversions are calls, `T(x)`, and bit casts are `bitcast(T, x)`, a keyword whose first argument is a type. |
| Pointers | `&x` takes an address; `p.*` dereferences. `p.x` reaches a field through a pointer, as in Zig, Odin, Jai, C3 and Zen C (owner, 2026-11-11). |
| Declarations | `x := v`, `x: T`, `x: T = v`. Constants are `const X := v` and `const X: T = v`. `x: T = undefined` (also as a field default) skips zero initialization. |
| Slices | `a[lo..hi]` excludes `hi` and `a[lo..=hi]` includes it; `a[..hi]`, `a[..=hi]` and `a[lo..]` leave one end open. There is no `a[..]`, because arrays convert to slices. A slice may be assigned to, as in C3: `a[1..3] = 0`. C3's start-and-count form `a[i:n]` is left out until real code needs it; `a[i..][..n]` takes `n` items from `i`. |
| Functions | `fn add(a: int, b: int) -> int { }`, `fn sq(x: int) -> int => x * x`; inline `fn(x) => e`. Parameters use the declaration forms, and may be untyped. |
| Named arguments | `f(.a = 1)` |
| Types | Prefix: `*T`, `?T`, `[]T`, `[N]T`, `[4, 4]T` (up to 4 dimensions, indexed `m[i, j]`), `fn(int, x: T) -> R`. Errors: `E!T` and `!T`. A written return type is a whole type, so a function that returns nothing writes `-> void`, `-> !void` or `-> E!void`, or leaves out `->` |
| Structs, enums and unions | `struct Point { x: int, y: int = 0 }`; `enum Color: u8 { red = 1, green }`; `union Bits { f: f32, u: u32 }`; `union Shape: u8 { circle: Circle, none }`. Members are separated by `,`, `;` or a line break. Keywords may be member names. |
| Literals | `Point.{ 1, 2 }`, `Point.{ .x = 1 }`, `.{ … }` when the type is known; arrays `.[1, 2, 3]` and `u8.[1, 2]`; enum values `.red`; `void`'s value `.{}` or `void.{}` |
| Control flow | `if` and `while` with optional parentheses; `for x in items`, `for x, i in items`; ranges `0..n` and `0..=n`; `switch x { 1, 2 => …, 0..10 => { … }, _ => … }` with no fallthrough, where a one-line arm ends at its line break; `defer` runs at block exit |
| Discard | `_` binds any number of times and is never read: `for _, i in`, `fn f(_: T)`, `_ = f()` |
| C interop | `export fn` makes a function callable from C. A C header is imported like a package, recognized by its `.h` path. |
