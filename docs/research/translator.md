# The C-to-chibi translator

Updated 2026-11-23. Item 5 of the self-hosting order ([README.md](README.md)) translates the compiler's C into chibi. The translator reads clang's JSON ASTs of the compiler's 11 C files in one run and writes the compiler as one chibi program, with each declaration once, in a chibi file named after the C file that defines it (3t.12). `make translated` translates the files listed in the Makefile's `BOOTSTRAP` from the AST of each target in turn, builds the program without `src/main.c`'s translation through `chibi c` after an empty entry file, so that its files are library files and may declare globals (3g.2), and runs the test suite with it in place of the C files, on x86-64 and on arm64 under qemu. It then builds the whole program into a compiler and checks that this compiler writes the same C for the program as the C build did (3t.10).

## Steps

- **3t.1 The reader and `src/arena.c`: built 2026-11-21.** The translator is written in C, the language recommended to the owner on 2026-11-21, so it follows the compiler's rules and can be translated with it later.
  - `translate/ast.c` streams the output of `clang -std=c23 -Xclang -ast-dump=json -fsyntax-only` into flat columns, one row per node in pre-order: the end of the node's subtree, its kind, location, type spelling, name, a detail (cast kind, operator, value or storage class), the declaration it refers to, and flags. clang leaves out a location's file and line when they repeat, so the reader carries them over from the previous location in the dump. The 500 MB dump of `src/lexer.c` loads in 0.9 s.
  - `translate/translate.c` parses type spellings, which are C declarators, into its own type table. It links each declaration to the first one and to the definition, so a prototype and its body share one set of pointer facts. It infers what each pointer can hold, then writes declarations, statements and expressions, adding `!!`, `bitcast`, conversions and parentheses where chibi needs them.
  - A translated file includes the structs it uses from project headers, an `extern fn` for each C function it calls, and any `static inline` function from a header that it calls.
  - Checked against a hand translation of `src/arena.c`: the structure is the same. The differences are the wrapping operators of rule 2, and `!!` on reads of locals where the hand translation relied on narrowing.
  - Tests: `make translated` passes with the translated `src/arena.c` on x86-64 under ASan and UBSan and on arm64 under qemu. The generic-SIMD and bulk-lexer builds pass too, run by hand.
- **3t.2 Constant tables and globals: built 2026-11-21.** Every table in the compiler's C is a `static const` array or struct, at file scope or inside a function, so most of this step is constant tables.
  - A table becomes a top-level constant with its type written out, `const arity: [12]u8 = .[0, 3, 2, 0, …]`, and a struct becomes `const poison := Pair.{ … }`. clang's AST lists each element in order, with a filler for the rest, so designated initializers and GNU ranges come out as whole arrays, which chibi requires.
  - Enum constants that the translated code uses become untyped constants, `const NODE_ADD := 1`, grouped by enum.
  - A long literal wraps: an array of arrays or structs puts one element on each line, and an array of numbers fills lines of up to 100 columns.
  - Tests: no compiler file translates with this step alone, because each one also needs strings, unions or `stderr`. A sample file with enum-indexed, 2-D, struct and `bool` tables, two static tables of one name in one function, a table whose row C takes as a pointer, and two mutable globals prints the same as clang's build of the C, under ASan and UBSan. `src/arena.c` translates to the same chibi as before, and `make translated` still passes.
- **3t.3 String literals and variadic C functions: built 2026-11-21,** after chibi's string literals (step 3k.3 in [checker-and-ir.md](checker-and-ir.md) section 8). `src/str.c` now translates too.
  - A literal is written as a chibi literal, and chibi converts it to the `*u8`, `[*]u8` or optional that the place it goes has, so the translator adds no `!!` or `bitcast` to it. clang's AST spells a literal with C's escapes inside JSON's, and the translator decodes both and writes chibi's escapes: `\"`, `\\`, `\b`, `\f`, `\n`, `\r`, `\t`, and `\u00XX` for the other control bytes, such as `\u001B` for C's `\e` and `\u0000` for `\0`.
  - A C function declared with `...` becomes an `extern fn` that ends in `..`, as in `extern fn printf(p0: ?[*]u8, ..) -> i32`.
  - A conditional under a conversion that changes nothing, as `const char *q = k ? "yes" : "no"` has, is found in a declaration, an assignment and a `return`, as one without it was.
  - Tests: `make translated` passes with `src/arena.c` and `src/str.c` translated, on x86-64 under ASan and UBSan and on arm64 under qemu. Nothing in the compiler calls `src/str.c`, so a test program in the scratchpad calls each of its functions on 5 strings, with slices that start past the end, and the translated file prints the same 155 lines as the C under ASan and UBSan. A sample with literals in a declaration, an argument, a compound literal, a `return`, a conditional and `printf`'s `..`, and with every escape that clang writes, prints the same as clang's build of the C.
- **3t.4 C's globals, `sizeof` of an expression, and `++` and `--` used as values: built 2026-11-21,** after chibi's `extern` globals (step 3h.6 in [checker-and-ir.md](checker-and-ir.md) section 8). `src/names.c` now translates too.
  - A C variable declared `extern`, such as `stderr`, becomes `extern stderr: *u8` beside the file's `extern fn` lines. The name comes from clang's AST, so on macOS, where `stderr` is a macro for `__stderrp`, the translation names `__stderrp`.
  - `sizeof x` becomes `size_of` of `x`'s type, as in `size_of(NameSlot)`, because chibi's `size_of` takes only a type.
  - `++` and `--` whose value is used become statements, so `x = a[i++];` comes out as `x = a[i]` followed by `i += 1`. A prefix `++x` puts `x += 1` before the statement that uses `x`. A postfix `x++` puts the increment after the statement when nothing in the statement can see `x` change: the statement is an expression or a declaration, and it calls nothing or `x` is a local or parameter whose address the function never takes. Otherwise the old value goes to a new local first, `x_old := x` and `x += 1`, and the statement uses `x_old`.
  - In a `while` condition, the loop becomes `while true { …; if !(c) { break } … }`, so the increments run before each test. In a `do … while` condition they come before the test's `if`, and in an `else if` condition the `else` gets braces, so that the increments sit inside it.
  - Refused: an increment on the right of `&&` or `||`, in a branch of `?:`, after a comma, inside `sizeof`, in an operand with another side effect, such as `a[n++]++`, in a `for` condition and in a `switch` value, because moving it out would change when it runs. None appears in `src/names.c`.
  - A pointer passed where a C function takes the same pointer type, such as `stderr` to `fprintf`, no longer goes through `bitcast`. The check compared nil facts for levels of pointer that the type doesn't have, and C functions without a body mark every level nullable. `src/str.c` loses 9 such `bitcast`s, and the C-vs-chibi comparisons of 3t.2 and 3t.3 print the same as before.
  - Tests: `make translated` passes with `src/arena.c`, `src/str.c` and `src/names.c` translated, on x86-64 under ASan and UBSan and on arm64 under qemu. A sample of 15 functions with increments in declarations, assignments, arguments, `return`, and the conditions of `if`, `while`, `do … while` and `else if`, with a call that reads the incremented global and a local whose address escapes into the called function, prints the same as clang's build of the C under ASan and UBSan, and 6 bodies with the refused forms fail to translate. The tests catch all 17 planted bugs in the translator: 15 through the sample, and 2, `sizeof` of the expression's own type and `stderr` written as a chibi global, through `make translated`. One passed at first: no case had a local whose address escapes, and the sample now has one.
- **3t.5 `?:` inside expressions, conditions used as integers, loops that count down, and the bit-scan and overflow builtins: built 2026-11-21,** after chibi's conditional expressions (step 3k.4 in [checker-and-ir.md](checker-and-ir.md) section 8) and a rewrite of `src/exact.c` without its union and 128-bit integers, which chibi lacks. No union or `__int128` is left in the compiler's C. `src/exact.c` now translates too.
  - `c ? a : b` becomes `if c then a else b` wherever it appears, in place of the `if` and `else` statements of 3t.3. Under a conversion to an integer type, a conditional whose values are all constants writes each one converted, as rule 3 does for one constant, so `base = p[1] == 'x' ? 16 : 8` for a `u32` becomes `base = if … then 16 else 8`. Without this, the values would be untyped under a `bitcast(u32, …)`, and chibi would give them `int`, which is 64 bits wide.
  - A condition used as an integer, as in `int x = a < b` or `exp -= cmp < 0`, becomes `if c then T(1) else T(0)`, in place of the labeled block of 3t.1. `|` and `&` between two conditions, as in `(s < v) | (t < s)`, become `or` and `and` when the right side has no side effects, because chibi's `or` and `and` skip their right side.
  - `__builtin_clzll(x)` and `__builtin_ctzll(x)` become `i32(leading_zeros(x))` and `i32(trailing_zeros(x))`.
  - `__builtin_add_overflow(a, b, &r)`, and the `sub` and `mul` forms, become `r = a +% b` before the statement and `add_overflows(a, b)` in its place, because chibi's overflow checks (step 3i.2) give no result. Refused: one that may not run, on the right of `&&` or `||` or in `?:` or `sizeof`; one whose operands have side effects or a type other than the result's; and one whose result is one of its operands or a variable whose address the function takes elsewhere, because the store that moves before the statement would change what the check reads. Since step 3k.26 one call gives both results (rule 13), so a result that is one of the operands translates.
  - `for (T i = n; i-- > k;)`, with a constant `k` of 0 or more, becomes `while i > k` with `i -= 1` first in the body, inside a block that declares `i`. `--i` in that place stays refused, as rule 21 refuses increments in a `for` condition.
  - Fixed: `p - n` with an unsigned `n` narrower than 64 bits became `p + -%n`, which wraps at `n`'s width, so the offset grew by 2^32. In `src/exact.c`, `digits + len - k` with a `u32` `k` crashed the tests. It is now `p + -%u64(n)`.
  - Tests: `make translated` passes with `src/arena.c`, `src/str.c`, `src/names.c` and `src/exact.c` translated, on x86-64 under ASan and UBSan and on arm64 under qemu. A sample of 43 functions prints the same as clang's build of the C under ASan and UBSan: conditionals as operands, arguments, nested values and pointers; constant values converted to `u32` and `u8`, and one beside a variable; conditions as integers in declarations, `return`, arguments, `+=`, `-=` and pointer `+=`; `|` between conditions with and without calls on its right, and `|` and `&` between integers in a condition; each builtin, also in an `else if` and a `while` condition; countdown loops with `continue`; and pointer minus `u32`, `u64` and `int`. 9 bodies with the refused forms fail to translate. The 3t.4 sample prints the same as before, and `src/arena.c`, `src/str.c` and `src/names.c` translate to the same chibi. The tests catch all 24 bugs planted in the translator: 23 through the sample, and 1, which drops the pointer kinds that the place of a conditional asks for, through `make translated`, where chibi refuses the `nil` that `src/arena.c` then puts beside a `*u8`. Two passed at first: `|` and `&` turned into `or` and `and` between integers, and a conditional treated as all constants when only its first value is. The sample now has both.
- **3t.6 Tables of strings, literals under pointer casts, `bool` indexes, and recursive functions without a result: built 2026-11-21,** after chibi's strings in constant tables (step 3k.5 in [checker-and-ir.md](checker-and-ir.md) section 8). `src/parser.c` now translates too.
  - A table of strings, such as `static const char *const node_labels[NNODES]`, becomes a constant of optional pointers, `const node_labels: [183]?[*]u8 = .[…]`, with `nil` where C leaves an element out. The translator needed no change for this, because rule 19 already leaves each literal untyped; chibi now accepts it.
  - clang puts a cast from `char *` to `const char *` on a literal that stands beside a `const char *` value in `?:`, as in `p->error = kind == TK_ANDAND ? "use `and` instead of `&&`" : msg`. The translator wrote that cast as `bitcast(?[*]u8, "…")`, which chibi refuses, because `bitcast` takes a typed value. A literal under a cast to a pointer to `u8` is now written alone, and chibi converts it to the pointer its place has. A literal cast to a pointer to anything else, as in `*(const int *)"abcd"`, is refused, because chibi's literals convert only to pointers to `u8`.
  - An index of type `bool`, as in `slice_nodes[has_start][inclusive]`, becomes `[if c then 1 else 0]`, because chibi indexes only with integers. clang doesn't promote an index, so the `bool` reaches the subscript as it is.
  - A `void` function that calls itself, or calls a function defined after it, gets `-> void`. Without `->`, chibi infers a private function's result from its body, and reports "`walk` depends on itself" when the body calls the function, directly or through a later one, before the result is known. 13 functions in `src/parser.c` get it, among them `parse_binary` and `parse_type`.
  - Tests: `make translated` passes with `src/arena.c`, `src/str.c`, `src/names.c`, `src/exact.c` and `src/parser.c` translated, on x86-64 under ASan and UBSan and on arm64 under qemu. A sample of 19 functions prints the same as clang's build of the C under ASan and UBSan: a table of strings with gaps, a table of structs that hold strings, literals beside a `const char *` in nested `?:`, literals cast to `const unsigned char *` in a nullable and a non-nullable local, `bool` parameters and comparisons as indexes, and `void` functions that recurse directly, through a later function, and after first calling an earlier one. 3 bodies that cast a literal to a pointer to `int`, `signed char` and `unsigned short` fail to translate. The samples of 3t.4 and 3t.5 print the same as before, and the other four files translate to the same chibi. The tests catch all 13 bugs planted in the translator, all through the sample. Four passed at first: a literal cast to a pointer to `signed char` or to a wider unsigned integer accepted, the cast literal no longer marked untyped, and `-> void` decided by the first call alone. The sample now has a body or a function for each.
- **3t.7 SIMD vectors, `memcpy` as loads and stores, and arrays of characters filled from strings: built 2026-11-22.** The translator now writes all of `src/lexer.c`, which joined `TRANSLATED` the same day, once step 3k.6 built `mul_high` for the 128-bit multiply in `src/names.h`'s identifier hash.
  - The AST of `src/lexer.c` is dumped with `-DCHIBI_SIMD_GENERIC`, so `src/simd.h` gives its portable C instead of SSE or NEON intrinsics, and the translation is the same on every host.
  - GNU vector types become chibi's, so `u8 __attribute__((vector_size(16)))` is `u8x16`. A scalar beside a vector is written alone, because chibi splats it. A comparison keeps its operands' vector type, so the `(__typeof__(a))` cast in `simd_eq` writes nothing, and a cast to another vector type becomes `bitcast`. Vector arithmetic wraps, as C's does.
  - Calls to `simd_lookup16` and `simd_mask16` become `lookup(t, i & 15)` and `u64(top_bits(v))`, which give what the generic C gives for every input, and their C loops aren't translated. `& 15` is left out when the index is `x & k` with `k` below 16 or `x >> k` with `k` of 4 or more, as in `lookup(lo_sets, v & 15)` and `lookup(hi_sets, v >> 4)`. It is needed elsewhere because chibi's `lookup` gives 0 for an index of 16 or more, where the generic C keeps the index's low 4 bits.
  - `memcpy(&x, p, n)` becomes `x = unaligned_load(T, p)` and `memcpy(p, &x, n)` becomes `unaligned_store(p, x)`, when `x` is a variable of integer or vector type and `n` is its size, written as a constant or with `sizeof`. Other copies stay calls to `memcpy`. A copy between two variables becomes a load from the source's address, so 2 lines of `src/exact.c` change, such as `b = unaligned_load(u32, bitcast([*]f32, &f))`.
  - An array of characters filled from a string, such as each row of `kind_names`, becomes an array of byte numbers padded with zeros to its length.
  - Smaller forms that `src/lexer.c` needs: a local array is declared with its type, because chibi can't infer one from `.[…]`; `~0ULL` becomes `~u64(0)`, because chibi takes an untyped `~0` as -1; `b |= c` and `b &= c` on a `bool` become `b = c or b` and `b = c and b`; an overflow builtin whose result is one of its operands, as in `o |= __builtin_add_overflow(sum, c, &sum)`, stores the result after the statement, when the statement is an expression or a declaration and nothing else in it reads the result, until step 3k.26 gave both results from one call; a struct parameter whose fields the body assigns is copied into a local, as rule 10 copies other assigned parameters; a local `enum` declares its constants at the top level; and a `static` function named like a builtin that translations call, such as the lexer's own `trailing_zeros`, gets a trailing `_`.
  - Tests: `make translated` passes with the five files of 3t.6 translated, on x86-64 under ASan and UBSan and on arm64 under qemu, and so does a copy that adds `src/lexer.c` with the hash computed in 32-bit halves. A sample of 35 functions prints the same as clang's build of the C under ASan and UBSan: vector arithmetic, comparisons and casts, a vector literal shorter than its type, each index form of `simd_lookup16` with indexes past 15, `simd_mask16` and `simd_mask64`, `memcpy` of whole and partial integers, vectors and arrays, arrays of characters with escapes and padding, a local `enum`, the overflow and `bool` forms above, a struct parameter assigned through its fields, and static functions named `trailing_zeros` and `lookup`. 3 bodies fail to translate: an overflow builtin in a condition, one whose result the statement also reads, and a `bool |=` whose target calls a function. The samples of 3t.4 to 3t.6 print the same as before, and the other five files translate to the same chibi apart from the 2 lines of `src/exact.c`. Of 38 bugs planted in the translator, the samples catch 36, and the 13 of 3t.6 are still caught. The other 2 change only the translation, which still passes the tests: a `bitcast` to the same type around vector comparisons, and `memcpy` calls kept where loads would do. In a first round, 18 of 48 plants passed the samples. 9 of them showed checks that never fire, which were removed, together with the rule that kept copies between two variables as `memcpy`, and with one of those checks gone a tenth is caught. The sample got cases for 5 more: escaped strings, a cast between vector types, a vector with 4 lanes, an overflow refusal whose operands have the result's type, so that only the rule under test refuses it, and every byte of a table of characters, because reading past the end of a string put bytes after the terminator, where neither the sample nor the lexer looked.
  - The hash, added after step 3k.6: `src/names.h` now computes it with `folded_multiply(a, b)`, which XORs the two halves of the 128-bit product, and the translator writes a call to it as `a *% b ^ mul_high(a, b)`. Both arguments must be variables, so writing them twice repeats no work, and other arguments are refused. Written in C as `a * b ^ mul_high(a, b)`, the hash cost the lexer 4.0 million more instructions on the timing corpus, a quarter of `intern_names`: the lexer keeps only the hash's low 32 bits, so clang narrowed `a * b` to a 32-bit `imul` beside the 128-bit `mul`, and spilled a pointer in the loop. The sample adds the hash, a slot index masked as the lexer masks it, a multiple of the result, a local named `mul_high`, and one refusal, and it catches all 9 bugs planted in the mapping.
- **3t.8 Function pointers, a translation for each target, floats, and the forms that `src/check.c`, `src/arm64.c` and `src/driver.c` need: built 2026-11-22,** after chibi's structs and arrays as the values of a conditional (step 3k.7) and `?extern fn` (step 3k.8). The three files now translate too, so 9 of the compiler's 11 C files are translated; `src/c_source.c` and `src/main.c` are left.
  - clang reads a file for one target, so `#if` is decided before the translator sees the AST. In `src/arm64.c` it chooses `PROT_EXEC` for the JIT's memory on arm64, `MAP_JIT` and `pthread_jit_write_protect_np` on Apple, the instruction-cache flush, and `CONVENTION_HOST` in `src/arm64.h`. `make translated` now translates each file twice: from the host's AST for the x86-64 run, and from an AST for `aarch64-linux-gnu` for the run under qemu. The two translations differ only in 5 lines of `src/arm64.c`, which add `PROT_EXEC` and the flush. With the x86-64 translation in both, the arm64 tests crashed at the first instruction of the JIT's code, because that view maps the memory without `PROT_EXEC`. One chibi source for every target needs conditionals on the target in chibi, which is a decision for the owner.
  - A pointer to a function becomes `extern fn(T, …) -> R`, or `?extern fn(…)` where rule 4 makes it nilable, as `qsort`'s comparator in `src/check.c` and `signal`'s handler in `src/driver.c` are. A function's name in a place that gives it a type is written alone, and chibi adds the adapter when the function is a chibi one. Refused: a function's name with nothing to give it a type, as in `h == on`; a pointer to a variadic function, because chibi's `extern fn` types can't end in `..`; and, as before, a call through a function pointer, which none of the files makes.
  - `__builtin___clear_cache(b, e)` becomes a call to `__clear_cache`, the runtime function that the builtin calls, with `extern fn __clear_cache(begin: ?[*]u8, end: ?[*]u8)`. The C backend gives the declaration its own name and the symbol through an asm label, so it doesn't clash with clang's builtin.
  - A float literal with an integer value below 2^128 is written with all its digits and `.0`, as `18446744073709551616.0`, because clang's AST spells it `2` or `1.8446744073709552E+19`. Any other value is written as clang spells it, such as `1.0000000000000001E+300`, which always has a `.`.
  - `__builtin_clz`, `__builtin_ctz` and `__builtin_popcount`, and `__builtin_popcountll`, become `leading_zeros`, `trailing_zeros` and `count_ones`, as the 64-bit forms of 3t.5 do.
  - A shift whose left side is a constant and whose right side is typed writes the constant with C's type, as `i32(1) << n` and `u64(1) << (at % 64)`. chibi gives an untyped constant the type of its place, so `x := 1 << n` would make `x` an `int`.
  - A conditional whose values are constants writes its first value with C's type where its place gives chibi no type, as in `n +% (if c then u64(1) else if d then u64(2) else 3)` or an argument to `snprintf`'s `..`, because chibi gives untyped values `int`.
  - A conditional between a pointer that may be nil and one that can't, which 3t.5 refused inside expressions, is now written when its condition proves the pointer isn't nil, as `p != NULL ? p : "none"` does: the pointer gets `!!`, which emits no check on a narrowed local. The proof reads `!`, `&&`, `||`, comparisons with `NULL`, and a bare test, so `!(p == NULL || q == NULL) ? q : "unset"` proves `q`. Where the place gives no type, a literal that comes first trades places with the other value and the condition is negated, so that the typed value comes first.
  - A nilable pointer stepped with `++`, `--`, `+=` or `-=` becomes `p = p!! + 1`, because chibi's `+=` doesn't unwrap. It is refused when `p` has side effects, as `(*pp())++` does, because the translation reads it twice.
  - `|=`, `&=` and `^=` on a narrow integer, which C promotes, as in `u8 |= u8`, are written at the target's type when the right side is a value of that type, widened, or constants: `f |= g`, `f &= u8(251)`, `f ^= if c then u8(1) else 2`. Other promoting compound assignments, such as `u16 |= u8` and `u8 += int`, stay refused.
  - Increments that 3t.4 refused move where they still run as in C. A declaration whose value is a conditional with an increment in a branch, as `int x = c ? a[i++] : a[j++]`, becomes an `if` that assigns each branch. An `if` without `else` whose condition is `a && b`, with an increment in `b`, becomes `if a { … if b { … } }`. A `while` whose condition is `a && b` keeps `a` in its header when `a` has no increment. A `switch` value's increments go before the `switch`.
  - A countdown loop, `for (T i = n; i-- > k;)`, takes any bound without an increment, such as a variable or a call, which runs once per test as in C, where 3t.5 took only a constant.
  - A `static_assert` is left out, because clang checks it when it reads the C. An enum constant whose value clang converts to the enum's type is read through the conversion. A literal under a cast to `void *`, as in `memcmp(p, "chibi", 5)`, is written alone, as one under a cast to a pointer to `u8` is.

The samples of 3t.4 to 3t.7 print the same as before, and the six files of 3t.7 translate to the same chibi apart from 2 lines of `src/exact.c` and 3 of `src/lexer.c`, where a shift's constant or a conditional's first value is now typed. The tests catch all 51 bugs planted in the translator for this step: 50 through the sample, and 1, which stops that check from skipping a builtin's name, through the 3t.7 sample, whose `__builtin_add_overflow` clang types as a variadic function. ## Rules chosen, open to review

1. **Integers** map by width and signedness. `char` becomes `u8`, unsigned as on arm64. `long` becomes `int`. `size_t` and `uintptr_t` become `u64`, not `uintptr`, so pointer-sized integers mix with other `u64` values without conversions.
2. **Unsigned arithmetic wraps.** Unsigned `+`, `-`, `*` and unary `-` become `+%`, `-%`, `*%` and `-%`, because C wraps them, and so does vector arithmetic. Signed operators stay checked, because C leaves their overflow undefined. So the compiler's unsigned arithmetic, which is most of it, loses chibi's overflow checks; a later pass can bring checks back where the tests show that nothing wraps.
3. **Conversions follow clang's casts.** A narrowing becomes `T(x & mask)`, which the checker emits as a truncation with no check. A sign change at the same width becomes `bitcast`. A signed value converted to a wider unsigned type becomes `bitcast(U, S(x))`, with `S` signed at the new width. A widening becomes `T(x)`. A constant whose value changes in the conversion, such as C's `-1` as a `u32`, is written as the converted value. `~` on an unsigned constant is written on a typed value, as `~u64(0)` for `~0ULL`, because chibi takes an untyped `~0` as -1, and so is a constant on the left of a shift whose right side is typed, as `i32(1) << n`. `|=`, `&=` and `^=` on a narrow integer, which C promotes, are written at the target's type when the right side has that type before C widens it, or is constants; other compound assignments that promote their target are refused.
4. **Nullable pointers.** A pointer is nullable if it is compared with `NULL`, tested as a condition, assigned `NULL`, zero-initialized (a global without an initializer, a field left out of a literal unless rule 31 finds it written first, or a pointer in memory from `calloc`), or given a value that may be nil. The facts flow along assignments, initializations, arguments and returns until nothing changes, apart from what rules 6, 32 and 33 hold back. A C function declared without a body returns nullable pointers and takes nullable pointers.
5. **Many-pointers.** A pointer becomes `[*]T` if it is indexed, offset with `+` or `-`, incremented, subtracted from another pointer, or compared with `<`. The kind spreads both ways along plain copies, so one value keeps one kind. `(U *)(p + 1)`, the idiom that steps over a header, doesn't make `p` a `[*]T`; the translation offsets a `bitcast` of it.
6. **Dereferenced parameters and locals stay non-nullable.** A parameter that the function dereferences before its first branch or `return` isn't made nullable by the arguments; the caller unwraps the argument with `!!` instead. That turns `use_chunk(a, c)` into `use_chunk(a, c!!)`, as in the hand translation, rather than adding `!!` to every use inside `use_chunk`. A local with an initializer that those statements dereference, and that the function never assigns, steps or takes the address of, isn't made nullable by its initializer: the initializer gets `!!`, as in `d := holds.maybe!!`, and the uses of `d` get none (3t.13).
7. **Uses.** A nullable pointer gets `!!` wherever it is dereferenced, offset, or passed where a non-nullable pointer is expected; on a narrowed local, `!!` emits no check. A nilable pointer stepped with `++`, `--`, `+=` or `-=` becomes `p = p!! + n`, refused when `p` has side effects. A field read through a `[*]T` is `p[0].f`. A value that moves between `*T` and `[*]T`, or to another pointee type, goes through `bitcast`.
8. **`void *`** becomes a pointer to `u8`, and so does a pointer to a struct from a system header, such as `FILE`.
9. **Pointer arithmetic that chibi lacks.** `p - q` becomes `(bitcast(int, p) - bitcast(int, q)) / mem.size_of(T)`, and `p < q` compares `bitcast(u64, p)` with `bitcast(u64, q)`. `p - n` becomes `p + -n` for a signed `n`, `p + -%n` for a 64-bit unsigned `n`, and `p + -%u64(n)` for a narrower unsigned `n`, or `p + -%u64(k)` for a constant `k`, because chibi has no `-` on a `[*]T`, refuses a constant negative offset, and widens an unsigned offset with zeros.
10. **Names.** A parameter that the body assigns, also through one of its fields, or whose address it takes, is renamed `name_in` and copied into a local `name`. A local that would shadow another gets a number. A C name that is a chibi keyword or a type name gets a trailing `_`; an exported function with such a name is refused. A local or parameter named after a built-in package that its function calls into, such as `bits` in a function that counts bits, gets a trailing `_` too, because it would hide the package (3k.15).
11. **Statements.**
    - A local without an initializer gets `= undefined`. A local array is declared with its type, as in `buf: [16]u8 = …`. A local `enum` declares its constants at the top level.
    - `for (T i = a; i < b; i++)`, where `b` is a constant or a local that the body doesn't write, becomes `for i in a..b`. Any other `for` becomes a `while` with the step at the end of the body, inside a block when the `for` declares a variable. If the body has a `continue`, a labeled block wraps it and `continue` becomes `break nextN`.
    - `for (T i = n; i-- > k;)`, where `k` is a constant of 0 or more or an expression without increments, becomes `while i > k { i -= 1; … }` inside a block that declares `i`.
    - An `if` without `else` whose condition is `a && b`, with an increment in `b`, becomes `if a { if b { … } }` with `b`'s increments between the two. A `while` whose condition is `a && b` keeps `a` in its header when `a` has no increment. A declaration whose value is `c ? x : y`, with an increment in `x` or `y`, becomes an `if` that assigns each branch.
    - `do … while (c)` becomes `while true { …; if !(c) { break } }`.
    - A `switch` arm drops its final `break`. Any other `break` out of a `switch` uses a label on the switch, because an unlabeled `break` in a chibi arm leaves the enclosing loop. An arm that falls into the next is refused. `_ => {}` is added when there is no `default`.
12. **`?:`** becomes `if c then a else b`. Under a conversion to an integer type, a conditional whose values are all constants writes each one converted. Inside another expression, a conditional between a pointer that may be nil and one that can't is refused, unless its condition proves that the first isn't nil; then that value gets `!!`. Where the place gives chibi no type, a conditional of constants writes its first value with C's type, and a literal that comes first trades places with the other value, with the condition negated.
13. **Builtins.** `assert(c)` becomes chibi's `assert(c)` (3t.15), and `assert(a && b)` becomes `assert(a)` and then `assert(b)` (3t.17). `__builtin_expect(x, y)` becomes `x`. A `bool` or a condition used as an integer becomes `if c then T(1) else T(0)`, and one used as an index becomes `[if c then 1 else 0]`, and `|` or `&` between conditions becomes `or` or `and` when its right side has no side effects. `b |= c` and `b &= c` on a `bool` become `b = c or b` and `b = c and b` when `b` has no side effects. `__builtin_clz`, `__builtin_ctz` and `__builtin_popcount`, and their `ll` forms, become `T(bits.leading_zeros(x))`, `T(bits.trailing_zeros(x))` and `T(bits.count_ones(x))`. `__builtin___clear_cache` becomes a call to `__clear_cache`. A `static_assert` is left out. `__builtin_add_overflow(a, b, &r)` and its `sub` and `mul` forms become `r, overflowed = bits.add_overflow(a, b)` before the statement, after `overflowed: bool = undefined`, and `overflowed` in its place (3k.26). A `bool` declared from one gets both results without the temporary: `bool o = __builtin_add_overflow(a, b, &r)` becomes `o: bool = undefined` and `r, o = bits.add_overflow(a, b)`. Refused, each with its own message: one on the right of `&&` or `||`, in a branch of `?:`, after a comma, inside `sizeof` or in a `for` condition; one whose operands or result have side effects; one whose result isn't a local or parameter whose address the function never takes; and one whose operands and result differ in type. `isfinite(x)` and `signbit(x)` in a condition become tests of `x`'s bits (3t.9).
14. **Functions** that aren't `static` become `export fn`, so C callers, such as the test suite, keep their symbols. A function that C marks `NOINLINE` or `ALWAYS_INLINE` gets `@noinline` or `@inline` (3t.11). C's `COLD`, which only hints, is left out (3t.16). A `void` function that calls itself or a function defined after it gets `-> void`, so chibi doesn't infer its result from a body that depends on it.
15. **Layout.** Blank lines between statements come from the source file. Comments are dropped. Macros appear expanded, so `ARENA_MAX_ALLOC` is written `u64(1) << 62`, and `#if` is decided for the target that clang reads the file for, so each target gets its own translation.
16. **Tables.** A `const` table becomes a chibi constant. One whose address C takes, as `const u64 *km = key_mask[n]` does, becomes a global variable instead, because chibi refuses `&` and slicing on a constant until rank 10 decides read-only data (3g.1); so does any global that isn't `const`. A table inside a function moves to the top level as `function_name`, numbered when a function has two of one name, because chibi has no `const` in a body.
17. **Elements of tables** are folded to numbers, as C computes them, so `[NODE_ADD] = 2 + (NODE_SUB != NODE_NONE)` is written `3`. An element that is just an enum constant keeps its name.
18. **Enums.** An enum type becomes `u32`, which is what C uses when no constant is negative, and none in the compiler is. Enum constants are untyped, as C's are plain integers, and clang's AST already shows each conversion they go through.
19. **String literals** stay untyped, so chibi converts each to the pointer its place needs. A literal under a cast to a pointer to `u8` or to `void` is written alone, and a cast to a pointer to anything else is refused. A control byte without a named escape and a byte from 0x7F on are written as `\xNN`, which chibi has since step 3k.20. An array of characters filled from a string becomes an array of byte numbers, padded with zeros to the array's length.
20. **Variadic C functions**, declared without a body, end in `..`. A variadic function with a body takes its extra arguments as `args: ..u64`: its `va_list` becomes an index, `va_arg(ap, T)` reads `args[ap]` as a `T` and steps the index after the statement, and each call converts its extra arguments to `u64` with their bits kept (3t.9). An exported one is refused, because its C callers pass C's `...`.
21. **Increments** whose value is used become statements: before the statement that uses them for `++x`, after it for `x++` when nothing in the statement can see the change, and otherwise through a local that keeps the old value, `x_old`. Where moving one would change when it runs, as on the right of `&&` outside the condition of an `if` without `else` or of a `while`, in a `for` condition or beside another side effect in the same operand, the translator refuses. `va_arg`'s step moves as `x++` does, with a local `arg` in place of `x_old`.
22. **C's global variables** become `extern` globals, with the name and type that clang's AST gives.
23. **`sizeof x`** becomes `mem.size_of(T)` with `x`'s type.
24. **Vectors.** GNU vector types become arrays of their lanes, as `[16]u8` (3k.22). A scalar beside a vector is written alone, because chibi splats it. A vector literal becomes an array literal of its element type, with a zero for each lane that C leaves out. A comparison becomes `simd.eq(a, b)`, `simd.ne`, `simd.lt`, `simd.le`, `simd.gt` or `simd.ge`, whose result keeps its operands' type, so a cast back to that type writes nothing, and a cast to another vector type becomes `bitcast`. `src/simd.h` is read in its generic form: `simd_lookup16(t, i)` becomes `simd.lookup(t, i & 15)`, without `& 15` when the form of `i` keeps it below 16, and `simd_mask16(v)` becomes `u64(simd.top_bits(v))`.
25. **`memcpy`** of a variable's whole value, an integer or a vector, becomes `mem.unaligned_load` or `mem.unaligned_store`. Other copies stay calls.
26. **`folded_multiply(a, b)`**, the helper in `src/names.h`, translates as written since step 3k.19, with `u128` for `__uint128_t`. Until then it became `a *% b ^ bits.mul_high(a, b)`, with both arguments variables.
27. **Function pointers** become `extern fn(T, …) -> R`, nilable by rule 4. A function's name is written alone where its place gives it a type. Refused: a function's name with nothing to give it a type, as in a comparison, a pointer to a variadic function, and a call through a function pointer.
28. **Float literals** with an integer value below 2^128 are written with all their digits and `.0`. Others are written as clang's AST spells them.
29. **Files.** The files of a program translate together into one chibi program (3t.12). Each declaration is written once, in the chibi file named after the C file that holds it: a C file and the header of its name give one chibi file, a function goes where its body is, a header without a C file of its name gives a file of its own, and declarations from system headers go into `extern.chibi`. A file whose code calls a builtin starts with an import of each built-in package it uses, as `import "std/bits"` (3k.15). Declarations that the files share are linked by their name when C links them, as a function or global variable that isn't `static`, and otherwise by their kind, name, file and place in it.
30. **Clashing names.** A `static` name that another file also declares at the top level takes the name of its chibi file as a prefix, as in `lexer_fail`. A struct, union or enum constant whose name another file gives to a different declaration is refused, and so is a new name that is taken.
31. **Fields written before they are read.** A pointer field that a struct literal leaves out isn't nullable when the statements after the literal's statement, in the same block, write it before anything may read it. A literal whose values are all zero or `NULL`, such as C's `{ 0 }`, leaves out every field (3t.16). The scan follows up to 128 statements while they are assignments, increments, declarations, calls to `malloc`, `calloc`, `realloc` or `free`, or calls that pass the address of a part of the struct to a function whose first statement fills that parameter's target with a literal, as `exacts_init(&c->exacts)` does, when neither the call's other arguments nor the function's statements read a field still unwritten. It stops at any other statement, at one that may read a field still unwritten, and where the variable or an object that holds the struct is assigned. A read is a use of the variable itself, a copy of any struct, a member access that reaches a field still unwritten, and an access to a field of the same declaration through another variable or through an expression that isn't a variable. A field written this way that no other literal leaves nil is declared `name: T = undefined`. The literal of a `return`, an argument, an array element, a `static` local or a declaration of several variables zeroes the fields it leaves out, as rule 4 says, and so does a literal with more than 256 pointer fields, counting those of the structs inside it (3t.13).
32. **Allocations.** A nil result from `malloc`, `calloc` or `realloc` makes a place nullable only if the program tests that place for nil, or passes the place's value on to a place that it tests, or reaches the place through a pointer, as `*pp`. Anywhere else the store gets `!!`, so running out of memory stops the translated program at the allocation, where the C would crash at the first use of the pointer (3t.13).
33. **Results that can't be nil.** A function that C marks `__attribute__((returns_nonnull))` returns a pointer that can't be nil, unless the program tests its result for nil. Its `return`s don't make its result nullable: a `return` of a value that may be nil gets `!!`, and an integer cast to a pointer is written `bitcast(*T, x)`, which trusts the mark as C does. A declaration with the mark in a header gives it to the definition (3t.14).
34. **Character constants** become chibi's character literals when the constant is the literal's own value and below 128: `'a'`, `'\n'`, or `'\x1B'` for a control byte without a named escape. Any other value, such as `'\xff'`, which is -1 where `char` is signed, or `u8'\xff'`, which is 255, is written as a number (3k.20).
35. **Narrowed locals.** A local with an initializer, or a parameter, that a test shows isn't nil doesn't make a place nullable when it flows there while the test holds, if the function never assigns it, steps it or takes its address. A test is `p != NULL` or `p == NULL`, either way round, `!p` or `p` alone, combined with `!`, `&&` and `||`. What it shows holds in the branch of the `if` that it leads to, `then` or `else`, on the right side of `&&` or `||`, and, after an `if` without `else` whose branch always ends in `return`, `break` or `continue`, in the rest of the block up to the next `case` or `default` label. One test covers up to 8 locals. The translation still writes `!!` on such a read where the place needs a pointer that can't be nil, and chibi, which narrows the local in the same places (step 3e.2), emits no check for it (3t.16).

## One source for every target

Updated 2026-11-22. The switch makes chibi the compiler's source (phase 2 of the Compiler row of 2026-11-17), and the source must then serve every target, where the C chooses with `#if`. clang decides `#if` before the translator reads the AST, so each target gets its own translation (3t.8).

What the C chooses by target:
- `src/arm64.h`: `CONVENTION_HOST`, Apple's calling convention on macOS and AAPCS64 elsewhere.
- `src/check.h`: since step 3k.13, `TARGET_OS_HOST` and `TARGET_ARCH_HOST`, the target that the checker folds `target_os` and `target_arch` for.
- `src/arm64.c`: for the JIT, `PROT_EXEC` on arm64; `MAP_JIT` and `pthread_jit_write_protect_np` on macOS on arm64; the instruction-cache flush, `sys_icache_invalidate` on macOS and `__builtin___clear_cache` on Linux, both on arm64.
- `src/driver.c`: `O_BINARY`, which only Windows defines.
- `src/simd.h`: NEON or SSSE3 code, which the translation avoids by reading the generic form, and `src/lexer.c`'s `CHIBI_LEXER_BULK`, a build option rather than a target.

On Linux, the x86-64 and arm64 translations differ in 7 lines: `PROT_EXEC`, the flush and, since step 3k.13, `TARGET_ARCH_HOST`. A macOS translation would differ in about 6 more. The translator can't write these tests, because the AST holds only the side that clang chose; the commit that makes chibi the source can merge the translations by hand where they differ, which phase 2 allows. What chibi needs is a way to write them:

- **A. Predeclared target constants and a plain `if`.** `target_os` and `target_arch` are predeclared, and `if target_arch == .arm64 { … }` is an ordinary `if`. Both branches are checked on every target, as Go checks code that tests `runtime.GOOS` ([runtime](https://pkg.go.dev/runtime#pkg-constants)); a branch that the target rules out emits no code, so a call to a function that only macOS has links elsewhere, as long as its `extern fn` is declared everywhere. In the C that `chibi c` writes, the test becomes a test of the C compiler's predefined macros, such as `__aarch64__`, so that C still builds for any target. Zig writes target tests the same way, as `if (builtin.cpu.arch == .aarch64)`, but its lazy analysis also leaves the untaken branch unchecked ([builtin](https://ziglang.org/documentation/0.15.2/#Compile-Variables)).
- **B. A `when` statement.** As Odin's `when ODIN_OS == .Windows { … }` ([overview](https://odin-lang.org/docs/overview/#when-statements)), Jai's `#if OS == .WINDOWS` and Nim's `when defined(arm64):`, the untaken branch is parsed but not checked, so it may name declarations that only another target has, and `when` also works at the top level to declare them. It needs a keyword and a rule for which declarations a top-level `when` may hold.
- **C. Files per target.** As Go's `_arm64.go` file names and `//go:build` lines ([cmd/go](https://pkg.go.dev/cmd/go#hdr-Build_constraints)) and Odin's `#+build` tags, the build picks a file for each target, and each file holds one target's code. It needs the package rules, which are still open, and splits the JIT setup of `arm64_compile` across files.

Recommended: A. It covers every test above without new syntax, since the compiler declares the functions that only macOS has as `extern fn` and never needs a declaration that only one target has. B can follow with compile-time code (sheet 7 in [syntax-options-abstraction.md](syntax-options-abstraction.md)), if a target ever lacks a type or function that another target's code needs.

Step 3k.13 builds A, which the owner chose on 2026-11-23 ([checker-and-ir.md](checker-and-ir.md), step 3k.13). It differs from the description above in one point: the checker folds the constants for its target, the host, and the C that `chibi c` writes refuses a C compiler for another target with `#error`, in place of testing the C compiler's macros, because a `const` needs the value while compiling and because clang keeps a ruled-out arm at `-O0` when the arm holds a loop's label. The commit that makes chibi the source still merges the two translations where they differ, and `chibi c` then needs `--target` to write the arm64 C on an x86-64 machine, which step 3k.14 adds.

**The switch, rehearsed 2026-11-22 at 8704f1b.** The x86-64 translation, with its 7 differing lines merged by hand into tests of `target_arch` (`prot`, the cache flush and its `extern fn`, and `TARGET_ARCH_HOST`), passes the tests and both bootstrap checks: on x86-64, and on arm64 under qemu, where the C that `chibi c --target arm64-linux` writes on x86-64 is the same, byte for byte, as the C that the arm64 build writes for itself. Translating the tests is the largest of the three ways. The C backend names struct fields by position (`f0`, `f1`), so the checks take the field names from the chibi source, as a written header would.
- **The bootstrap C.** Phase 2 keeps a C build only to bootstrap. With the target constants folded, `chibi c` writes C for one target, so the bootstrap C is one file per target, 4.2 MB each, and the Makefile's universal macOS build would compile two C files and join them with `lipo` in place of one `-arch arm64 -arch x86_64` compile.
- **A run on macOS.** Until a Mac builds and runs the merged source, its macOS lines are unrun.
