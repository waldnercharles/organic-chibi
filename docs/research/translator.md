# The C-to-chibi translator

Updated 2026-11-21. Item 5 of the self-hosting order ([README.md](README.md)) translates the compiler's C into chibi. The translator reads clang's JSON AST of one C file and writes a chibi file. `make translated` translates the files listed in the Makefile's `TRANSLATED`, builds each one through `chibi c` after an empty entry file, so that it is a library file and may declare globals (3g.2), and runs the test suite with them in place of the C files, on x86-64 and on arm64 under qemu.

## Steps

- **3t.1 The reader and `src/arena.c`: built 2026-11-21.** The translator is written in C, the language recommended to the owner on 2026-11-21, so it follows the compiler's rules and can be translated with it later.
  - `translate/ast.c` streams the output of `clang -std=c23 -Xclang -ast-dump=json -fsyntax-only` into flat columns, one row per node in pre-order: the end of the node's subtree, its kind, location, type spelling, name, a detail (cast kind, operator, value or storage class), the declaration it refers to, and flags. clang leaves out a location's file and line when they repeat, so the reader carries them over from the previous location in the dump. The 500 MB dump of `src/lexer.c` loads in 0.9 s.
  - `translate/translate.c` parses type spellings, which are C declarators, into its own type table. It links each declaration to the first one and to the definition, so a prototype and its body share one set of pointer facts. It infers what each pointer can hold, then writes declarations, statements and expressions, adding `!!`, `bitcast`, conversions and parentheses where chibi needs them.
  - A translated file includes the structs it uses from project headers, an `extern fn` for each C function it calls, and any `static inline` function from a header that it calls.
  - Checked against a hand translation of `src/arena.c`: the structure is the same. The differences are the wrapping operators of rule 2, and `!!` on reads of locals where the hand translation relied on narrowing.
  - Tests: `make translated` passes with the translated `src/arena.c` on x86-64 under ASan and UBSan and on arm64 under qemu. The generic-SIMD and bulk-lexer builds pass too, run by hand.
- **3t.2 Constant tables and globals: built 2026-11-21.** Every table in the compiler's C is a `static const` array or struct, at file scope or inside a function, so most of this step is constant tables.
  - A table becomes a top-level constant with its type written out, `const arity: [12]u8 = .[0, 3, 2, 0, …]`, and a struct becomes `const poison := Pair.{ … }`. clang's AST lists each element in order, with a filler for the rest, so designated initializers and GNU ranges come out as whole arrays, which chibi requires.
  - Enum constants that the translated code uses become untyped constants, `const NODE_ADD := 1`, grouped by enum.
  - A long literal wraps: an array of arrays or structs puts one element on each line, and an array of numbers fills lines of up to 100 columns.
  - Tests: no compiler file translates with this step alone, because each one also needs strings, unions or `stderr`. A sample file with enum-indexed, 2-D, struct and `bool` tables, two static tables of one name in one function, a table whose row C takes as a pointer, and two mutable globals prints the same as clang's build of the C, under ASan and UBSan. `src/arena.c` translates to the same chibi as before, and `make translated` still passes.
- **3t.3 String literals and variadic C functions: built 2026-11-21,** after chibi's string literals (step 3k.3 in [checker-and-ir.md](checker-and-ir.md) section 8). `src/str.c` now translates too.
  - A literal is written as a chibi literal, and chibi converts it to the `*u8`, `[*]u8` or optional that the place it goes has, so the translator adds no `!!` or `bitcast` to it. clang's AST spells a literal with C's escapes inside JSON's, and the translator decodes both and writes chibi's escapes: `\"`, `\\`, `\b`, `\f`, `\n`, `\r`, `\t`, and `\u00XX` for the other control bytes, such as `\u001B` for C's `\e` and `\u0000` for `\0`.
  - A C function declared with `...` becomes an `extern fn` that ends in `..`, as in `extern fn printf(p0: ?[*]u8, ..) -> i32`.
  - A conditional under a conversion that changes nothing, as `const char *q = k ? "yes" : "no"` has, is found in a declaration, an assignment and a `return`, as one without it was.
  - Tests: `make translated` passes with `src/arena.c` and `src/str.c` translated, on x86-64 under ASan and UBSan and on arm64 under qemu. Nothing in the compiler calls `src/str.c`, so a test program in the scratchpad calls each of its functions on 5 strings, with slices that start past the end, and the translated file prints the same 155 lines as the C under ASan and UBSan. A sample with literals in a declaration, an argument, a compound literal, a `return`, a conditional and `printf`'s `..`, and with every escape that clang writes, prints the same as clang's build of the C.
- **3t.4 C's globals, `sizeof` of an expression, and `++` and `--` used as values: built 2026-11-21,** after chibi's `extern` globals (step 3h.6 in [checker-and-ir.md](checker-and-ir.md) section 8). `src/names.c` now translates too.
  - A C variable declared `extern`, such as `stderr`, becomes `extern stderr: *u8` beside the file's `extern fn` lines. The name comes from clang's AST, so on macOS, where `stderr` is a macro for `__stderrp`, the translation names `__stderrp`.
  - `sizeof x` becomes `size_of` of `x`'s type, as in `size_of(NameSlot)`, because chibi's `size_of` takes only a type.
  - `++` and `--` whose value is used become statements, so `x = a[i++];` comes out as `x = a[i]` followed by `i += 1`. A prefix `++x` puts `x += 1` before the statement that uses `x`. A postfix `x++` puts the increment after the statement when nothing in the statement can see `x` change: the statement is an expression or a declaration, and it calls nothing or `x` is a local or parameter whose address the function never takes. Otherwise the old value goes to a new local first, `x_old := x` and `x += 1`, and the statement uses `x_old`.
  - In a `while` condition, the loop becomes `while true { …; if !(c) { break } … }`, so the increments run before each test. In a `do … while` condition they come before the test's `if`, and in an `else if` condition the `else` gets braces, so that the increments sit inside it.
  - Refused: an increment on the right of `&&` or `||`, in a branch of `?:`, after a comma, inside `sizeof`, in an operand with another side effect, such as `a[n++]++`, in a `for` condition and in a `switch` value, because moving it out would change when it runs. None appears in `src/names.c`.
  - A pointer passed where a C function takes the same pointer type, such as `stderr` to `fprintf`, no longer goes through `bitcast`. The check compared nil facts for levels of pointer that the type doesn't have, and C functions without a body mark every level nullable. `src/str.c` loses 9 such `bitcast`s, and the C-vs-chibi comparisons of 3t.2 and 3t.3 print the same as before.
  - Tests: `make translated` passes with `src/arena.c`, `src/str.c` and `src/names.c` translated, on x86-64 under ASan and UBSan and on arm64 under qemu. A sample of 15 functions with increments in declarations, assignments, arguments, `return`, and the conditions of `if`, `while`, `do … while` and `else if`, with a call that reads the incremented global and a local whose address escapes into the called function, prints the same as clang's build of the C under ASan and UBSan, and 6 bodies with the refused forms fail to translate. The tests catch all 17 planted bugs in the translator: 15 through the sample, and 2, `sizeof` of the expression's own type and `stderr` written as a chibi global, through `make translated`. One passed at first: no case had a local whose address escapes, and the sample now has one.
- **3t.5 `?:` inside expressions, conditions used as integers, loops that count down, and the bit-scan and overflow builtins: built 2026-11-21,** after chibi's conditional expressions (step 3k.4 in [checker-and-ir.md](checker-and-ir.md) section 8) and a rewrite of `src/exact.c` without its union and 128-bit integers, which chibi lacks. No union or `__int128` is left in the compiler's C. `src/exact.c` now translates too.
  - `c ? a : b` becomes `if c then a else b` wherever it appears, in place of the `if` and `else` statements of 3t.3. Under a conversion to an integer type, a conditional whose values are all constants writes each one converted, as rule 3 does for one constant, so `base = p[1] == 'x' ? 16 : 8` for a `u32` becomes `base = if … then 16 else 8`. Without this, the values would be untyped under a `bitcast(u32, …)`, and chibi would give them `int`, which is 64 bits wide.
  - A condition used as an integer, as in `int x = a < b` or `exp -= cmp < 0`, becomes `if c then T(1) else T(0)`, in place of the labeled block of 3t.1. `|` and `&` between two conditions, as in `(s < v) | (t < s)`, become `or` and `and` when the right side has no side effects, because chibi's `or` and `and` skip their right side.
  - `__builtin_clzll(x)` and `__builtin_ctzll(x)` become `i32(leading_zeros(x))` and `i32(trailing_zeros(x))`.
  - `__builtin_add_overflow(a, b, &r)`, and the `sub` and `mul` forms, become `r = a +% b` before the statement and `add_overflows(a, b)` in its place, because chibi's overflow checks (step 3i.2) give no result. Refused: one that may not run, on the right of `&&` or `||` or in `?:` or `sizeof`; one whose operands have side effects or a type other than the result's; and one whose result is one of its operands or a variable whose address the function takes elsewhere, because the store that moves before the statement would change what the check reads.
  - `for (T i = n; i-- > k;)`, with a constant `k` of 0 or more, becomes `while i > k` with `i -= 1` first in the body, inside a block that declares `i`. `--i` in that place stays refused, as rule 21 refuses increments in a `for` condition.
  - Fixed: `p - n` with an unsigned `n` narrower than 64 bits became `p + -%n`, which wraps at `n`'s width, so the offset grew by 2^32. In `src/exact.c`, `digits + len - k` with a `u32` `k` crashed the tests. It is now `p + -%u64(n)`.
  - Tests: `make translated` passes with `src/arena.c`, `src/str.c`, `src/names.c` and `src/exact.c` translated, on x86-64 under ASan and UBSan and on arm64 under qemu. A sample of 43 functions prints the same as clang's build of the C under ASan and UBSan: conditionals as operands, arguments, nested values and pointers; constant values converted to `u32` and `u8`, and one beside a variable; conditions as integers in declarations, `return`, arguments, `+=`, `-=` and pointer `+=`; `|` between conditions with and without calls on its right, and `|` and `&` between integers in a condition; each builtin, also in an `else if` and a `while` condition; countdown loops with `continue`; and pointer minus `u32`, `u64` and `int`. 9 bodies with the refused forms fail to translate. The 3t.4 sample prints the same as before, and `src/arena.c`, `src/str.c` and `src/names.c` translate to the same chibi. The tests catch all 24 bugs planted in the translator: 23 through the sample, and 1, which drops the pointer kinds that the place of a conditional asks for, through `make translated`, where chibi refuses the `nil` that `src/arena.c` then puts beside a `*u8`. Two passed at first: `|` and `&` turned into `or` and `and` between integers, and a conditional treated as all constants when only its first value is. The sample now has both.

## Rules chosen, open to review

1. **Integers** map by width and signedness. `char` becomes `u8`, unsigned as on arm64. `long` becomes `int`. `size_t` and `uintptr_t` become `u64`, not `uintptr`, so pointer-sized integers mix with other `u64` values without conversions.
2. **Unsigned arithmetic wraps.** Unsigned `+`, `-`, `*` and unary `-` become `+%`, `-%`, `*%` and `-%`, because C wraps them. Signed operators stay checked, because C leaves their overflow undefined. So the compiler's unsigned arithmetic, which is most of it, loses chibi's overflow checks; a later pass can bring checks back where the tests show that nothing wraps.
3. **Conversions follow clang's casts.** A narrowing becomes `T(x & mask)`, which the checker emits as a truncation with no check. A sign change at the same width becomes `bitcast`. A signed value converted to a wider unsigned type becomes `bitcast(U, S(x))`, with `S` signed at the new width. A widening becomes `T(x)`. A constant whose value changes in the conversion, such as C's `-1` as a `u32`, is written as the converted value.
4. **Nullable pointers.** A pointer is nullable if it is compared with `NULL`, tested as a condition, assigned `NULL`, zero-initialized (a global without an initializer, or a field left out of a literal), or given a value that may be nil. The facts flow along assignments, initializations, arguments and returns until nothing changes. A C function declared without a body returns nullable pointers and takes nullable pointers.
5. **Many-pointers.** A pointer becomes `[*]T` if it is indexed, offset with `+` or `-`, incremented, subtracted from another pointer, or compared with `<`. The kind spreads both ways along plain copies, so one value keeps one kind. `(U *)(p + 1)`, the idiom that steps over a header, doesn't make `p` a `[*]T`; the translation offsets a `bitcast` of it.
6. **Dereferenced parameters stay non-nullable.** A parameter that the function dereferences before its first branch or `return` isn't made nullable by the arguments; the caller unwraps the argument with `!!` instead. That turns `use_chunk(a, c)` into `use_chunk(a, c!!)`, as in the hand translation, rather than adding `!!` to every use inside `use_chunk`.
7. **Uses.** A nullable pointer gets `!!` wherever it is dereferenced, offset, or passed where a non-nullable pointer is expected; on a narrowed local, `!!` emits no check. A field read through a `[*]T` is `p[0].f`. A value that moves between `*T` and `[*]T`, or to another pointee type, goes through `bitcast`.
8. **`void *`** becomes a pointer to `u8`, and so does a pointer to a struct from a system header, such as `FILE`.
9. **Pointer arithmetic that chibi lacks.** `p - q` becomes `(bitcast(int, p) - bitcast(int, q)) / size_of(T)`, and `p < q` compares `bitcast(u64, p)` with `bitcast(u64, q)`. `p - n` becomes `p + -n` for a signed `n`, `p + -%n` for a 64-bit unsigned `n`, and `p + -%u64(n)` for a narrower unsigned `n`, or `p + -%u64(k)` for a constant `k`, because chibi has no `-` on a `[*]T`, refuses a constant negative offset, and widens an unsigned offset with zeros.
10. **Names.** A parameter that the body assigns, or whose address it takes, is renamed `name_in` and copied into a local `name`. A local that would shadow another gets a number. A C name that is a chibi keyword or type name gets a trailing `_`.
11. **Statements.**
    - A local without an initializer gets `= undefined`.
    - `for (T i = a; i < b; i++)`, where `b` is a constant or a local that the body doesn't write, becomes `for i in a..b`. Any other `for` becomes a `while` with the step at the end of the body, inside a block when the `for` declares a variable. If the body has a `continue`, a labeled block wraps it and `continue` becomes `break nextN`.
    - `for (T i = n; i-- > k;)`, with a constant `k` of 0 or more, becomes `while i > k { i -= 1; … }` inside a block that declares `i`.
    - `do … while (c)` becomes `while true { …; if !(c) { break } }`.
    - A `switch` arm drops its final `break`. Any other `break` out of a `switch` uses a label on the switch, because an unlabeled `break` in a chibi arm leaves the enclosing loop. An arm that falls into the next is refused. `_ => {}` is added when there is no `default`.
12. **`?:`** becomes `if c then a else b`. Under a conversion to an integer type, a conditional whose values are all constants writes each one converted. Inside another expression, a conditional between a pointer that may be nil and one that can't is refused.
13. **Builtins.** `assert(c)` becomes `if !c { abort() }`, with `extern fn abort()`. `__builtin_expect(x, y)` becomes `x`. A `bool` or a condition used as an integer becomes `if c then T(1) else T(0)`, and `|` or `&` between conditions becomes `or` or `and` when its right side has no side effects. `__builtin_clzll` and `__builtin_ctzll` become `T(leading_zeros(x))` and `T(trailing_zeros(x))`. `__builtin_add_overflow(a, b, &r)` and its `sub` and `mul` forms become `r = a +% b` before the statement and `add_overflows(a, b)` in its place; 3t.5 lists the forms refused.
14. **Functions** that aren't `static` become `export fn`, so C callers in the mixed build keep their symbols.
15. **Layout.** Blank lines between statements come from the source file. Comments are dropped. Macros appear expanded, so `ARENA_MAX_ALLOC` is written `u64(1) << 62`.
16. **Tables.** A `const` table becomes a chibi constant. One whose address C takes, as `const u64 *km = key_mask[n]` does, becomes a global variable instead, because chibi refuses `&` and slicing on a constant until rank 10 decides read-only data (3g.1); so does any global that isn't `const`. A table inside a function moves to the top level as `function_name`, numbered when a function has two of one name, because chibi has no `const` in a body.
17. **Elements of tables** are folded to numbers, as C computes them, so `[NODE_ADD] = 2 + (NODE_SUB != NODE_NONE)` is written `3`. An element that is just an enum constant keeps its name.
18. **Enums.** An enum type becomes `u32`, which is what C uses when no constant is negative, and none in the compiler is. Enum constants are untyped, as C's are plain integers, and clang's AST already shows each conversion they go through.
19. **String literals** stay untyped, so chibi converts each to the pointer its place needs. A byte above 0x7F is refused for now, because none appears in the compiler's literals and chibi has no escape for a single such byte.
20. **Variadic C functions** end in `..`. A variadic function with a body is refused, because chibi functions can't be variadic.
21. **Increments** whose value is used become statements: before the statement that uses them for `++x`, after it for `x++` when nothing in the statement can see the change, and otherwise through a local that keeps the old value, `x_old`. Where moving one would change when it runs, as on the right of `&&`, in a `for` condition or beside another side effect in the same operand, the translator refuses.
22. **C's global variables** become `extern` globals, with the name and type that clang's AST gives.
23. **`sizeof x`** becomes `size_of(T)` with `x`'s type.

## Not built yet

- Character literals, which wait on the owner's answer (asked 2026-11-21), become numbers meanwhile.
- Arrays of characters filled from string literals, as `src/lexer.c`'s `kind_names` is.
- Tables of strings and string-valued globals, which wait for chibi to place addresses inside constant data, and `static const char NAME[] = "..."`, which `src/arm64.c` and `src/driver.c` have and which could become a named chibi literal.
- Nested and unnamed records, function pointers, compound assignments that promote their target (`u8 += int`), the increments that rule 21 refuses, `switch` fallthrough, SIMD intrinsics, and `__builtin_clz` and `__builtin_ctz` on 32-bit values.
- Each translated file carries its own copy of chibi's runtime, `chibi_trap` and `chibi_context`, so the mixed build renames them per file with `-D`. Once the whole compiler is translated, it is one program and the renames go away.
